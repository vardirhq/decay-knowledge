# Learn Decay

This course teaches Decay by making visible game behaviour, not by marching through grammar in isolation.

## Course

1. **Your first script** — script declarations, `@export`, `var`, `f32`, `update`, `dt`.
2. **Values and types** — `let`, `var`, booleans, strings, numbers, entities and typed values.
3. **Functions** — parameters, return values and extracting behaviour.
4. **Control flow** — conditions and bounded repetition.
5. **Vectors** — `Vec2`, `Vec3`, components, length, normalization and common movement math.
6. **Entities and scripts** — `this`, entity-owned components and script identity.
7. **Scripts working together** — typed script references/messages.
8. **Events** — announce typed occurrences to interested systems.
9. **Shared state** — project-wide typed data and when it is preferable to messages/events.
10. **Collections and timers** — arrays/maps where supported and gameplay timing.
11. **Putting it together** — a small complete gameplay system using the concepts above.

## Teaching rule

Every lesson should answer four questions:

1. What problem are we solving?
2. What Decay feature solves it?
3. Why is this preferable to the obvious alternatives?
4. Where is the exact reference if I need edge cases?

A learner should see something change in the game early and often. The course is not a compiler-construction seminar wearing a game-engine hat.
